# 피자 주문 만족도 조사 대시보드 계획서

## 1. 프로젝트 목표

기존의 피자 주문 화면, 설문 조사 화면, 학습 진도 대시보드 화면을 하나로 연결한다.

사용자는 피자를 주문한 뒤 만족도 설문을 작성하고, 제출이 완료되면 주문 및 설문 결과를 대시보드 형태로 확인할 수 있다.

이번 1차 구현에서는 Streamlit의 `st.session_state`에 데이터를 저장한다. Supabase 연동은 기본 흐름을 완성한 다음 단계에서 진행한다.

---

## 2. 활용할 기존 파일

| 기존 파일 | 가져올 기능 | 변경할 내용 |
|---|---|---|
| `pizza.py` | 피자 선택 버튼, 주문 입력 폼, 상태 초기화 | 주문 검증과 주문 완료 상태를 추가한다. |
| `survey.py` | 화면 전환, 설문 완료 상태, 다양한 입력 컴포넌트 | 일반 설문을 피자 만족도 설문으로 변경한다. |
| `dashboard.py` | 넓은 화면, 지표, 필터, 표, 차트, 탭 | 학습자 데이터를 주문 및 만족도 데이터로 변경한다. |

세 파일을 직접 서로 import하기보다는, 필요한 기능을 하나의 새 Streamlit 파일에 정리해서 통합한다.

---

## 3. 전체 사용자 흐름

```text
앱 시작
  ↓
피자 선택 및 옵션 입력
  ↓
주문 내용 확인 및 주문 확정
  ↓
만족도 설문 작성
  ↓
설문 제출
  ↓
주문·설문 결과 대시보드 표시
  ↓
새 주문 시작
```

화면 전환은 반복문이 아니라 `st.session_state.page` 값으로 관리한다.

| `page` 값 | 표시할 화면 |
|---|---|
| `"order"` | 피자 주문 화면 |
| `"survey"` | 만족도 설문 화면 |
| `"dashboard"` | 결과 대시보드 |

---

## 4. 화면별 구성

### 4.1 피자 주문 화면

- `st.columns(3)`으로 Pizza 1, Pizza 2, Pizza 3 버튼 배치
- 피자 버튼을 누르면 기본 도우, 치즈, 토핑 값을 입력란에 표시
- 사용자가 기본 옵션을 직접 수정할 수 있도록 구성
- `st.form("pizza_order_form")` 안에 주문 확인 버튼과 초기화 버튼 배치
- 피자를 선택하지 않았거나 필수 옵션이 비어 있으면 `st.warning()` 표시
- 주문 확인이 성공하면 주문 정보를 저장하고 `page = "survey"`로 변경

주문 데이터 예시:

```python
order_data = {
    "pizza": "Pizza 1",
    "dough": "thin",
    "cheese": "mozzarella",
    "topping": "pepperoni",
}
```

### 4.2 만족도 설문 화면

- 상단에 주문한 피자와 옵션 요약 표시
- 닉네임 입력
- 전체 만족도: `st.slider(1, 5)`
- 맛 만족도: `st.slider(1, 5)`
- 배달 또는 제공 속도 만족도: `st.slider(1, 5)`
- 다시 주문할 의향: `st.radio()`
- 좋았던 항목: `st.multiselect()`
- 추가 의견: `st.text_area()`
- 모든 입력은 `st.form("satisfaction_form")` 안에 배치
- 필수 문항을 확인한 뒤 설문 데이터 저장
- 제출 성공 시 `page = "dashboard"`로 변경

설문 데이터 예시:

```python
survey_data = {
    "nickname": "Kim",
    "overall_score": 5,
    "taste_score": 4,
    "speed_score": 5,
    "reorder": "예",
    "liked_points": ["맛", "토핑"],
    "comment": "다시 주문하고 싶어요.",
}
```

### 4.3 결과 대시보드

페이지 설정:

```python
st.set_page_config(
    page_title="피자 만족도 대시보드",
    page_icon="🍕",
    layout="wide",
)
```

상단 핵심 지표:

- 총 주문 수
- 평균 전체 만족도
- 평균 맛 만족도
- 재주문 의향 비율

필터:

- 피자 종류
- 최소 만족도

탭 구성:

1. `주문 결과`
   - 방금 주문한 피자와 옵션
   - 작성한 만족도 응답
2. `응답 목록`
   - 필터링된 주문·설문 데이터를 `st.dataframe()`으로 표시
3. `만족도 차트`
   - 피자별 평균 만족도 막대 차트
   - 만족도 항목별 점수 차트

하단에 `새 주문 시작` 버튼을 두고 주문 및 설문 입력 상태를 초기화한 뒤 `page = "order"`로 돌아간다.

## 5. 상태값 설계

초기 상태는 한 함수에서 빠짐없이 생성한다.

```python
def init_state():
    defaults = {
        "page": "order",
        "pizza": "",
        "dough": "",
        "cheese": "",
        "topping": "",
        "order_data": {},
        "survey_data": {},
        "responses": [],
    }
```

| 상태값 | 역할 |
|---|---|
| `page` | 현재 표시할 화면 |
| `pizza`, `dough`, `cheese`, `topping` | 주문 폼 입력값 |
| `order_data` | 확정된 주문 한 건 |
| `survey_data` | 제출된 설문 한 건 |
| `responses` | 대시보드에 사용할 통합 응답 목록 |

설문 제출 시 `order_data`와 `survey_data`를 합쳐 `responses`에 추가한다.

## 6. 먼저 수정해야 할 기존 코드 문제

기존 `03_pizza.py`의 내용을 옮겨 작업할 `pizza.py`에서 확인된 항목:

- `pizza` 초기화 조건이 `"pizza"`가 아니라 `"dow"`로 되어 있다.
- `make_p2()`와 `make_p3()`에서 `pizza` 값을 저장하지 않는다.
- `make_p3()`가 P2의 도우, 치즈, 토핑 값을 저장한다.
- 선택하지 않은 상태에서도 제출할 수 있으므로 검증이 필요하다.
- 주문 완료 여부를 저장하지 않아 설문 화면으로 안전하게 전환할 수 없다.

기존 `01.AllServey.py`의 내용을 옮겨 작업할 `survey.py`에서 변경할 항목:

- 로그인 기능은 이번 피자 주문 흐름의 필수 기능이 아니므로 1차 구현에서 제외한다.
- 일반 인적사항 문항을 피자 만족도 문항으로 교체한다.
- 설문 버튼은 `st.form_submit_button()`으로 변경한다.
- 설문 제출 후 완료 문구만 표시하지 않고 대시보드로 이동한다.

기존 `04_student-progress-dashboard.py`의 내용을 옮겨 작업할 `dashboard.py`에서 변경할 항목:

- 마지막 `st.warning()` 뒤에 붙어 있는 불필요한 `0727` 문자열을 제거한다.
- `course`, `progress`, `score` 필드를 피자 종류와 만족도 점수로 교체한다.
- 데이터가 없을 때 평균값과 차트가 오류 없이 표시되도록 처리한다.

## 7. 구현 순서

### 1단계: 주문 화면 정리

- 피자별 기본값 수정
- 주문 입력 검증
- 주문 확정 데이터 생성
- 설문 화면으로 이동 확인

### 2단계: 만족도 설문 연결

- 피자 관련 문항 구성
- 필수값 검증
- 주문과 설문 데이터 합치기
- 대시보드 화면으로 이동 확인

### 3단계: 대시보드 구성

- 통합 데이터를 pandas DataFrame으로 변환
- 상단 지표 계산
- 피자 및 만족도 필터 적용
- 표와 차트 탭 구성

### 4단계: 초기화 및 예외 처리

- 새 주문 시작 기능
- 데이터가 없을 때 안내 메시지
- 빈 값 또는 잘못된 상태에서 다음 화면으로 이동하지 않는지 확인

### 5단계: 향후 Supabase 연동

- 주문 테이블과 만족도 테이블 설계
- 설문 제출 시 Supabase에 저장
- 대시보드에서 전체 고객 응답 조회
- 여러 사용자가 입력해도 데이터가 유지되도록 개선

---

## 8. 완료 기준

- 피자를 선택하지 않으면 주문을 확정할 수 없다.
- 피자를 선택하면 기본 옵션이 입력란에 표시되고 수정할 수 있다.
- 주문 확정 후에만 만족도 설문이 나타난다.
- 설문 필수값이 없으면 제출되지 않는다.
- 설문 제출 후 주문 내용과 만족도 결과가 대시보드에 표시된다.
- 필터를 변경하면 지표, 표, 차트가 같은 기준으로 변경된다.
- 새 주문 시작 버튼을 누르면 이전 입력값이 초기화된다.
- 각 단계에서 버튼을 눌러도 예상하지 않은 중복 저장이 발생하지 않는다.
